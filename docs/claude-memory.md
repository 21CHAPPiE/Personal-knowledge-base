# Claude 的记忆系统是怎么工作的

这篇文档不是这个项目的功能文档，是应用户要求写的一份"说明书"——解释 Claude（我）自己
那套跨会话记忆到底是什么、怎么触发、存在哪、格式是什么。写这篇的直接原因：`skills/kb/SKILL.md`
里"什么情况该往知识库写一条进展记录"这条标准，直接照抄了这套系统的判断标准，所以有必要把原
版讲清楚。

## 先破除一个误解：这不是"记忆"，是一个我会主动读写的文件

没有任何底层机制让我在两次对话之间"记得"发生过什么——每次新会话开始，我对之前所有对话都是
完全空白的，跟第一次见面一样。真正发生的事情是：

1. 我在某次对话里，把值得记住的东西，**主动写成一个 markdown 文件**，存在磁盘上一个固定目录里。
2. 下一次新会话开始时，我会去读这个目录，把里面的文件当作"别人（其实是我自己上次）留的笔记"
   加载进来。

所以这套系统的本质是**外部文件 + 显式读写约定**，不是我大脑里长出了什么。跟这个知识库项目做的
事情，原理上是一回事——只是我的这套记忆系统范围窄得多、格式严得多，专门只存一种东西：**行为
准则**，不是任意知识。

## 存在哪

每个项目目录对应一个独立的记忆文件夹，比如这个项目对应：

```
/home/oem/.claude/projects/-home-oem-Personal-knowledge-base/memory/
```

换一个项目目录，就是完全不同的一份记忆——不共享。这次会话开始时我检查过这个目录，**当时是空
的**：这个项目至今一条记忆都没存过。这个事实本身就说明了下一节的问题。

## 什么情况才会真的存一条

不是"发生了什么我都记一下"。触发条件很窄，只有一种：**用户纠正了我，或者明确表达了一个以后
还会用到的标准做法**。具体到三个必须同时满足的测试：

- **applicable（用得上）**——这条内容真的会改变我以后的行为或决定，不是单纯的背景信息，也不
  是我自己得出的一个技术结论。关键点：必须是用户教我的，不能是我自己调查代码/工具发现的东西。
- **durable（持久）**——这个标准在多次、多个任务里都成立，不是这一次任务的临时计划或状态。
  用户话里如果带"以后都…"、"每次都…"这种词，倾向于持久；带"这次…"、"暂时…"这种词，倾向于
  不持久。
- **legible（说得清）**——写成完整、干净的句子，一个文件只讲一件事，不能是速记或者"那个问题"
  这种事后看不懂的指代，要包含"为什么"，不只是"是什么"。

这次整个对话——搭鉴权、配 frp、修 MCP、建 skill、这些全都是我自己动手做的工程工作，不是"用户
纠正了我的某个通用行为习惯"，所以按这套标准，**一条都不该存进我的记忆**，也确实一条都没存。

## 存的格式

一个文件一条记忆，纯 markdown 加一段 YAML frontmatter：

```markdown
---
name: 简短的kebab-case标识
description: 一句话概括
metadata:
  pinned: false   # 最多 4 条能设成 true，代表"每次对话都要生效"的最高优先级标准
---

完整、干净、能独立读懂的正文内容，讲清楚是什么、为什么。
```

## 一个重要的自我提醒

即使存进去了，我也被要求把这些记忆当成"过去的快照去对照当下核实，而不是绝对真理"——用户的
偏好、项目的状态都可能变，旧记忆可能已经过时，不能盲信。

## 这跟你的个人知识库是什么关系

正因为我的记忆系统只存"用户教我的行为准则"这一种窄类型，**这次会话里发生的所有工程细节、决策
过程、踩过的坑，如果不主动写进你的这个知识库项目，就会随着这次对话结束彻底消失**——不会自动
变成我的记忆，因为它们根本不满足"用户纠正我的通用习惯"这个门槛。这正是你说的"这个工具是连接
我和别的 AI 的知识大脑"这句话的准确含义：我的原生记忆管我"该怎么做事"，你的知识库管"做过什么
事、知道什么事"——两者不重叠，也不能互相替代。
